# Rules, Expectations, and Goals

There are any number of reasons to establish lab rules encompassing safety, philosophy, and expectations. This is how I want our research group to operate:

## General Rules

- Do good science by asking questions early and often, planning ahead, and collaborating.
- Give credit where credit is due.
- Highly Qualified Personnel (HQP, such as students and post-docs) should be the first author of papers coming from their thesis work. Authorship should be discussed early and generally follows the [ESA's Code of Ethics](https://www.esa.org/about/code-of-ethics/) – see also the advice of [Schmidt (1987)](https://www.jstor.org/stable/20166549), [Hunt (1991)](https://doi.org/10.1038/352187a0), and [Weltzin et al. (2006)](https://doi.org/10.1890/1540-9295(2006)4[435:AIEAAA]2.0.CO;2).
- Be safe and help others be safe by thinking critically about what training is needed.
- Publish in [Open Access](http://www.carl-abrc.ca/advancing-research/scholarly-communication/open-access/) venues whenever possible, noting different requirements from each funder.
- Deposit all publications and technical reports on a preprint server such as [bioRxiv](https://www.biorxiv.org/), [EarthArXiv](https://eartharxiv.org/), [ESSOAr](https://www.essoar.org/), etc.
- All data must be organized and stored on the group's [GitHub organization](https://github.com/biogeochem) with the metadata template completed.
- Make all data and code available for each publication via a repository like [Borealis](https://borealisdata.ca/dataverse/laurier), [GitHub+Zenodo](https://guides.github.com/activities/citable-code/), [Pangaea](https://pangaea.de/), etc.
- Have fun.

## Specific Rules

- It is important to interact with others in the group. Although our work hours are flexible, being around between 09:30 and 14:00 several days per week helps build community—though we recognize this has become harder with rising living costs in Waterloo and the shift toward remote work.
- We used to hold routine lab meetings (except during the peak field season), and attendance is expected. These sessions provide an opportunity to present new ideas, discuss data, and practice presentations. We actively work to maintain these regular meetings.
- Everyone should attend at least one conference or workshop per year, assuming funds and time permit, and is expected to apply for supplementary travel grants. Please share your abstract with co-authors at least one week in advance.
- Everyone needs to complete WHMIS training. Field personnel must hold Standard First Aid (for work near populated areas) or Wilderness First Aid (for remote locations). Anyone operating a boat requires a [Pleasure Craft Operator Card](https://www.tc.gc.ca/eng/marinesafety/debs-obs-paperwork-paperwork_operator-360.htm). Risk assessment forms and emergency contacts must be kept on file in the department. **No one does fieldwork alone.**

## Onboarding

Here is the checklist of onboarding tasks to help integrate new members into the group.

### Safety

- [ ] Get a OneCard and ask Jason to submit access requests for the [CCRWS](https://www.wlu.ca/academics/research/partnerships/gnwt/centre-for-cold-regions-and-water-science.html) and [SRC](https://students.wlu.ca/campus-services/classrooms-and-spaces/labs-and-equipment/science-research-centre.html) buildings, as well as the [Map Library](https://library.wlu.ca/locations/geography-resource-centre).
- [ ] Complete Standard or Wilderness First Aid (typically coordinated in May with the Dean of Science office) and email a copy to Jason for our files.
- [ ] Complete the Canadian Firearms Safety Course if working in northern field sites, and email a copy to Jason.
- [ ] Complete WHMIS, Compressed and Liquified Gas Training, and Laboratory Safety training [available via MyLearningSpace](https://mylearningspace.wlu.ca/d2l/lms/legacy/selfregistration.d2l?ou=6605), and email confirmation/certificates to Jason.
- [ ] Obtain a Pleasure Craft Operator Card and email a copy to Jason.

### Other

- [ ] Find your designated office space.
- [ ] Learn how to process financial/reimbursement requests through Loris.

### Data & Computing

#### We use Git and GitHub to manage code, data, metadata, and manuscripts:

- [ ] Create a [GitHub](https://github.com/) account with a profile picture, and ask Jason to add you to the appropriate [biogeochem teams](https://github.com/orgs/biogeochem/teams).
- [ ] [Create a new repository on GitHub](https://docs.github.com/en/repositories/creating-and-managing-repositories/creating-a-new-repository) with a README file.
- [ ] Edit your README using [Markdown formatting](https://docs.github.com/en/get-started/writing-on-github/getting-started-with-writing-and-formatting-on-github/basic-writing-and-formatting-syntax).
- [ ] Install [Git](https://git-scm.com/downloads).
- [ ] Install a Git GUI client like [Sourcetree](https://www.sourcetreeapp.com/) or [GitKraken](https://www.gitkraken.com/) to simplify version control workflows.

#### We primarily use R and RStudio for analysis, modeling, and visualization (alongside Python, Jupyter, or MATLAB as needed):

- [ ] Download and install [R](https://cloud.r-project.org/).
- [ ] Download and install [RStudio Desktop](https://posit.co/downloads/).
- [ ] Open RStudio to verify a clean installation. *(Note: Windows users may need [`Rtools`](https://cran.r-project.org/bin/windows/Rtools/) and Mac users [`Xcode`](https://developer.apple.com/xcode/) to compile certain packages).*
- [ ] Install core packages (`tidyverse`, `usethis`, and `here`) via the RStudio package manager or console.
- [ ] New programmers should work through the Data Carpentry [Introduction to R](https://datacarpentry.org/R-ecology-lesson/01-intro-to-r.html) and [Starting with data](https://datacarpentry.org/R-ecology-lesson/02-starting-with-data.html) tutorials.
- [ ] Vaccinate your global git configuration against stray files using [`usethis::git_vaccinate()`](https://usethis.r-lib.org/reference/git_vaccinate.html).
- [ ] Practice creating a repository from our [project template](https://github.com/biogeochem/project_template), fill out the metadata, commit, and push to GitHub.
